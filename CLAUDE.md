## Planned work from MakerFlow

Development briefs drafted in MakerFlow's project chat arrive as GitHub issues
labelled `makerflow-brief` (`gh issue list --label makerflow-brief`). When asked
what to work on, or to pick up a brief, check those first. Treat the issue as the
spec (ask if it leaves something important open), and reference it in the PR
(`Closes #N`) so merging closes it.
